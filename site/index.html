Fast triangulation of polygons (simple and with holes).

Simple polygons. Interior holes. No added points.

Triage combines three algorithms to handle small polygons and large geographic boundaries.

Triage draws on ideas from theoretical computational geometry, including monotone chains and implicit vertical decomposition, whose practical benefits emerge on sufficiently large inputs. Such polygons arise in GIS applications, for example in detailed country, state, and county boundaries.

01 / THE ALGORITHM

Three paths.
One triangulator.

01

Small polygons

Up to 64 vertices, without holes: ear cutting with a compact mask of live reflex vertices.

02

Small domains with holes

Up to 32 total vertices: join a hole when it blocks an ear, then continue cutting.

03

Larger inputs

Sweep monotone chains, insert diagonals between original vertices, and triangulate compact boundary ranges.

Read how chain-monotone triangulation works ↗

Also available in C++ and Julia: triangulate_bounded, a separate strategy with an O(n log n) worst-case time bound. It uses a balanced sweep status and sorted endpoint directions. The C++ version now combines Triage's chains with a BCG-style preallocated AVL tree: about 9% less time on large geographic rings and 39% less on the largest comb than the previous bounded backend. Julia's corresponding experiment was mixed, so its public backend stays unchanged. Measurements ↗ · Algorithm ↗

03 / ADVERSARIAL INPUTS

Worst-case inputs.

Two constructed families expose different weaknesses. These are stress tests, not a representative GIS workload or a claim to be the slowest possible inputs.

A comb: bad for default Triage

A simple polygon with many teeth creates a large active set before earlier intervals disappear. Repeated scans cost quadratic time, even with no holes. The bounded strategy uses tree searches; Earcut finds easy local ears and wins on this family.

Stacked holes: bad for Earcut

A rectangle containing a vertical stack of small rectangular holes produces sharply increasing Earcut times. Quadrupling the hole count increases its measured time about 60–69×. This suggests cubic growth over these sizes; we have not proved an asymptotic lower bound or isolated the dominant internal stage.

C++ median timings in milliseconds for one domain, with 12 warmed samples. All reported outputs pass exact coverage checks. An exact dyadic shear resolves x-coordinate ties.

04 / GET STARTED

Two implementations.
The same geometry.

C++17

Header-only · Boost headers
#include <triage/triage.hpp>

std::vector<triage::Point> points{
    {0,0}, {4,0}, {5,4}, {1,5},
    {1.5,1}, {2,2}, {3,1}
};
auto mesh = triage::triangulate(
    points, {0,4,7});

Zero-based indices. Flat coordinate storage.

Julia

Native Julia · no runtime dependencies
using Triage

points = Point[
    (0,0), (4,0), (5,4), (1,5),
    (1.5,1), (2,2), (3,1)
]
triangles = triangulate(
    points, [1,5,8])

One-based indices. Inline coordinate tuples.

Call triangulate_bounded explicitly to select the optional strategy in either language. It is available on main; the earlier v0.1.0 release predates this API.

05 / CHECKS & SCOPE

Vibe programming.
Explicit verification.

Created using Codex, with the algorithms, tests, scripts, and measurements available for inspection.

117,425 certified domains. The bounded C++ and Julia implementations produce byte-identical meshes on 117,415 corpus domains and ten adversarial domains. Independent exact-arithmetic checks certify orientation and boundary coverage. ASan/UBSan passed 118,708 generated and corpus cases. The default still reproduces every published corpus mesh.

Input assumptions matter. Triage expects simple boundaries and disjoint interior holes. The current chain path requires distinct x coordinates. It does not implement Earcut’s malformed-input recovery. The default can incur quadratic work; the optional bounded strategy guarantees O(n log n) arithmetic operations under the same input assumptions.
